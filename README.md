# PingCode｜账户与信号运营系统

基于分享会话中最新八页 UI 说明和前端 MVP 源码实现的可交互工作台。使用深蓝导航、蓝白卡片、表格、侧栏详情和中文运营流程。

## 业务功能

- 数据概览：账户池、A/B 分级、交付与反馈漏斗、优先触达账户。
- 账户管理：搜索、战役/等级/行业筛选、评分排序、分页、多选、CSV 导入去重与导出、新建及编辑。
- 账户详情：工商档案、招聘信号、角色研究、跟进记录、评分依据及运营建议。
- 信号字典：定义信号、查看来源与适用战役、更新验证结论。
- 招聘监控：关键词筛选、岗位详情、关联账户。
- 工商洞察：企业主库、ICP 匹配与风险提示；上传爱企查 .xlsx 文件新增企业及补全已有账户，支持 27 个工商字段、工作表选择、主体匹配、字段预览及勾选导入。
- SDR 交付：创建完整任务、批量待补充任务、交付/接受/退回状态、反馈保存。
- 反馈与规则：结果统计、信号验证、权重配置与规则历史版本。

## 数据与范围

企业、招聘和历史趋势为明确标注的演示数据，不能作为真实客户购买意图依据。没有接入真实工商、招聘、CRM API。股权关系和联系人只展示待核实的研究方向，不伪造个人联系方式。工作台的交付状态不会发送邮件或即时消息。

用户新增及修改的账户、任务、反馈、信号与规则保存到平台 D1 数据库。浏览器存储仅用于侧栏偏好。网站保持创建时的私有访问权限。当前不包含应用内多角色权限或外部数据采集引擎。

## 评分与交付

账户评分 = 六项评分按权重求和 − 风险值 × 20%，四舍五入并限制在 0–100。
默认权重为 ICP 25%、信号20%、时机15%、角色15%、产品15%、数据置信度10%。
A 类 ≥75；B 类 60–74；<60 暂缓，后端拦截交付。新规则立即影响当前评分，历史规则版本保留。

交付状态：待交付 → 已交付 → SDR已接受 → 已反馈。
已交付可退回待补充信息，补充后回到待交付。批量生成的任务先进入待补充信息，避免缺少依据直接交付。

## 实现

React + TypeScript + Vinext；Shadcn/Radix 控件；Cloudflare Worker 路由；D1 + Drizzle 迁移。

- `app/workspace.tsx`：界面与业务交互
- `app/globals.css`：设计与响应式布局
- `lib/model.ts`：类型、演示数据、评分函数
- `lib/storage.ts`：数据库与原子演示数据初始化
- `app/api/workspace/route.ts`：带校验的业务 API
- `db/schema.ts`、`drizzle/`：数据库结构与迁移

## 验证

TypeScript 检查与生产构建通过。`.checks/api-integration.mjs` 使用内存 SQLite 运行真实业务路由，验证初始化幂等、新建/编辑、评分、低分拦截、交付状态、反馈、批量任务、CSV 去重和规则校验。测试不会修改线上数据。

当前环境的受管浏览器预览不可用，因此未完成浏览器逐屏验收或 WebMCP 运行验证。WebMCP 按支持情况注册 `list_accounts` 和 `open_account`，不支持时不影响正常界面。

## Excel 工商资料补全

入口：“设置 → 工商数据上传 → 上传工商 Excel”。可下载不含企业数据的空白模板。仅支持 .xlsx，最大 5 MB，不限制上传企业总数；27 个表头与爱企查导出保持一致。文件在浏览器解析，确认后自动按行数和请求字节分批，仅将所选结构化字段保存到 D1，原始 Excel 不上传存储。

企业按全称（仅规范空格和中英文括号）或已有统一社会信用代码匹配，未匹配企业自动新增，不按简称模糊匹配。名称与有效代码冲突、同文件重复企业、缺少企业名称的记录均跳过；预览按每页 50 行分页，全文件主体匹配和重复检查先完成再分批保存。新增企业直接从 Excel 提取名称、行业、地区、成立日期、网址和经营范围；负责人和战役为“待分配”，员工规模为“待核实”，评分为 0，后续可编辑完善。

默认仅补全空的工商字段，也可选择用 Excel 非空值更新已有工商字段。空值、“-”和“待核实”等占位值不清空资料。工商字段独立保存于账户的 `business`，导入文件名及时间保存于 `businessImport`；展示时优先使用这些字段，未导入字段保留原档案回退值。经营状态、参保人数与运营状态、员工规模分开保存。主体匹配和字段白名单在服务端再次校验，每批写入使用事务并检测并发修改，界面显示保存进度。批次失败时保留已完成结果，未完成行可继续重试；重复请求中的已补全字段可安全跳过。

检查：`node .checks/business-import.mjs` 验证模板、超过 1000 行解析及匹配、全文件去重和自动分批；`node .checks/api-integration.mjs` 验证持久化、填空/更新、空值和主体冲突拦截。测试仅使用内存数据库，不修改线上资料。

新增企业与已有企业更新在同一批事务提交。新增时以规范化企业名称和信用代码在元数据表中占用唯一标识，避免并发重复建档；失败批次可重试，重试会重新匹配已经存在的企业。预览区分新增与更新，完成后分别显示数量。

非 18 位信用代码不再阻止导入：按企业全称匹配，原值保存并在预览和档案提示待核实；仅格式符合的 18 位代码参与主体匹配、文件去重及并发标识占用。异常代码不会覆盖已有合法代码。完成提示区分已保存、需核对和无需更新行数。

## 三级行业分类

按国民经济行业分类 GB/T 4754—2017（2019年修改），一级=门类、二级=大类、三级=中类。标准字典来源及许可见 `vendor/industry-taxonomy.SOURCE.md` 和 `.LICENSE`。优先使用 Excel 原始“所属行业”，缺失时使用账户行业；保留原值，分类另存为 `industryClassification`。仅依据标准名称、代码和明确层级路径匹配：行业字段不够细时下级标为“待细分”，无法匹配时一级标为“待分类”。不使用企业名称或经营范围猜测。

已有企业在读取时自动分类，无需重传；新导入及行业更新时同步生成分类。账户管理和工商洞察支持三级联动筛选，列表、详情和 CSV 导出包含三个层级。`node .checks/industry.mjs` 验证三级映射及不确定情况。

### 三级行业运营细分

当原始行业仅能定位到大类时，在该大类范围内根据经营范围关键词细分到国标中类。标准名称直接匹配的三级行业保持不变。优先覆盖互联网接入、信息服务、平台、安全、数据，以及软件开发、集成电路设计、系统集成、运维、数据处理、咨询、数字内容等方向。每条推断保留依据并标记“推断 · 待核实”。无足够依据或多业务方向分数接近时，存在对应“其他”中类则暂归该类并标记“暂归 · 待核实”；不跨越登记行业的大类推断。该分类为运营辅助，不代表重新确认企业法定主营业务。历史明确行业别名可映射并保留推断标记。

## 应用内文档

导航“文档”提供 12 个可搜索章节，解释各板块用途、数据关联、评分公式及 A/B 门槛、行业推断、Excel 导入、交付状态和反馈统计。评分章节读取当前生效规则与权重；证据打分建议与系统强制校验分开说明。可从章节直接打开对应业务板块，原使用说明弹窗也有完整文档入口。

文档新增“P0 战役：质量追溯与工具替换”章节，说明固定标题与快捷筛选行为、两类业务问题及证据、人工归类步骤、单主战役约束，以及行业、评分与 SDR 门槛之间的区别。

工商数据洞察增加分页：默认每页50条，支持预设20/50/100/200、自定义正整数条数、首末页和页码跳转。筛选与每页条数变化回到第一页，分页不影响导出当前筛选的全部结果。
